## 1. 氣泡排序法 (Bubble Sort)
* **原理簡述：** 重複走訪要排序的數列，一次比較兩個相鄰的元素，如果它們的順序錯誤（如前大後小）就進行交換。每一輪走訪會將目前未排序部分中最大的元素「浮」到數列的最後端。
* **複雜度分析：**
  * 時間複雜度：平均與最壞為 $O(n^2)$，最佳為 $O(n)$。
  * 空間複雜度：$O(1)$。
* **模擬實作：** 適合處理小規模數據，當數據量增加時，其大量的交換操作會導致效能劇烈下降。

## 2. 選擇排序法 (Selection Sort)
* **原理簡述：** 將數列分為「已排序」與「未排序」兩部分。每次從未排序部分中找出最小的元素，存放到已排序部分的末尾。
* **複雜度分析：**
  * 時間複雜度：最佳、最壞或平均皆為 $O(n^2)$。
  * 空間複雜度：$O(1)$。
* **模擬實作：** 雖然資料移動次數較少，但時間複雜度恆定，大數據量下表現不佳。

## 3. 插入排序法 (Insertion Sort)
* **原理簡述：** 模仿人類整理撲克牌的方式。將數列分為已排序和未排序，每次取出一張未排序的牌，從後往前掃描已排序部分，找到適當位置並插入。
* **複雜度分析：**
  * 時間複雜度：平均與最壞為 $O(n^2)$，最佳為 $O(n)$。
  * 空間複雜度：$O(1)$。
* **模擬實作：** 在資料量小或資料已近乎排序好的情況下，效能非常優異。

## 4. 合併排序法 (Merge Sort)
* **原理簡述：** 採用分治法 (Divide and Conquer)。將原始陣列切分成最小單位（長度為 1），再將這些子陣列兩兩合併，並在合併過程中進行排序。
* **複雜度分析：**
  * 時間複雜度：最佳、最壞或平均皆為 $O(n \log n)$。
  * 空間複雜度：$O(n)$。
* **模擬實作：** 效能穩定且為穩定排序，但需要額外的記憶體空間。

## 5. 快速排序法 (Quick Sort)
* **原理簡述：** 同樣採用分治法。選定一個基準值 (Pivot)，將小於基準值的移到左邊，大於的移到右邊，再對左右兩邊遞迴執行此動作。
* **複雜度分析：**
  * 時間複雜度：平均為 $O(n \log n)$，最壞為 $O(n^2)$。
  * 空間複雜度：$O(\log n)$。
* **模擬實作：** 實務上速度最快的演算法，因為其內部迴圈在大多數架構上效能極佳。

## 7. 學習心得

透過本次排序演算法的實作與分析，我深刻體會到「沒有最好的演算法，只有最適合的演算法」。
1. **複雜度的威力：** 當數據規模 $n$ 增加時，理論複雜度的差異會轉化為顯著的運行時間差距，$O(n \log n)$ 的優勢非常明顯。
2. **空間與時間的取捨：** 合併排序法雖然時間很快，卻需要額外空間；快速排序則提供了很好的原地排序效能。
3. **實作經驗：** 這次作業讓我學會如何將抽象的理論與實際的效能測試結合，並利用 GitHub Pages 呈現結果，這對程式開發能力的提升非常有幫助。
